# ADR 0008: Authenticated Web MVP and durable evidence jobs

- Status: Accepted
- Date: 2026-08-21

## Context

CaseMesh Core, private original storage, ingestion, Matter Brain merge/correction, and professional export existed as platform-neutral services, but a pilot user could not complete that evidence workflow through an authenticated web workspace. The Web MVP must preserve the existing epistemic, provenance, tenant-isolation, immutability, and privacy-deletion boundaries.

## Decision

Add a .NET 10 ASP.NET Core API/BFF in `src/CaseMesh.Api` and a Next.js/TypeScript application in `web`.

Authentication uses an external OpenID Connect authorization-code flow with PKCE and a server-managed cookie. OIDC tokens are not persisted to browser storage. Every environment outside the explicit `Testing` harness fails startup when HTTPS origin or OIDC configuration is absent, and deterministic test authentication, scanner, OCR, and extraction adapters cannot run elsewhere. Every workspace operation resolves the external issuer/subject to a relational `web_users` row and rechecks `tenant_memberships` server-side.

Migration `0006_web_mvp.sql` adds provider-neutral users, owner/member memberships, safe document filename metadata, and durable processing jobs. Matter-owned web rows retain composite tenant/Matter foreign keys plus forced RLS. Membership RLS uses transaction-local `casemesh.user_id`; Matter access sets both user and tenant contexts inside one transaction. Neither context is left on a pooled connection. Runtime roles can read only their own membership and cannot insert memberships directly. A narrowly scoped security-definer operation creates a new tenant and its initial owner atomically, so it cannot be used to self-enrol into an existing tenant.

Uploads have a complete-request limit and bounded multipart sections. The BFF computes SHA-256 while copying to a private temporary file, registers the immutable logical original in the domain, stores bytes through `IOriginalEvidenceStore`, and enqueues a tenant-scoped job. If storage or job persistence fails, the endpoint removes newly created bytes and the unexposed document/version/job state; a compensation failure is explicit and retryable. Object keys remain generated by the S3 adapter and are never accepted from or returned to a browser. A bounded in-process worker claims durable rows with `FOR UPDATE SKIP LOCKED`, uses explicit leases, periodically discovers persisted work independently of in-memory signals, and applies bounded retries. A session advisory lock fences each job's ingestion and Matter Brain writes so an expired lease cannot be reclaimed while its prior worker remains active. Typed failure logs omit evidence content and hashes. This is deliberately a single-service pilot worker; a later deployment may split the same protocol into a separately hosted process.

Production processing uses the existing scanner/OCR/parser abstractions and CLI adapters. The explicit `Testing` environment uses synthetic clean/OCR and structured-extraction adapters so a deterministic browser test can exercise upload through correction and export without external model calls. Test adapters cannot run under Production configuration.

The API is same-origin through the Next.js BFF rewrite. It uses secure/HTTP-only SameSite cookies, antiforgery tokens on state-changing API calls, authenticated-user rate-limit partitions, bounded forms, fixed non-sensitive ProblemDetails, a per-response nonce-based CSP, clickjacking/content-type/referrer/permissions headers, and no wildcard CORS. Normal logs contain job identifiers, typed failure codes, and exception types, never evidence bodies, hashes, or exception messages.

The UI presents attributed assertions, exact source-span citations, immutable document-version identity, contradictions, workplace records, factual open questions, audited correction, and private export. It repeatedly states that extraction confidence is not truth confidence and that an attributed statement is not automatically an established fact.

## Consequences

The generic Core remains independent of ASP.NET Core, OIDC, Next.js, PostgreSQL authentication tables, and provider SDKs. Existing Windows/SQLite/Live code remains unchanged. PostgreSQL and S3 remain the commercial system-of-record and original-byte boundaries.

Workspace display names are intentionally neutral in the first membership list projection because tenant-table RLS cannot be weakened during pre-tenant membership discovery. Rich workspace administration, invitations, provider-specific organisation groups, billing, legal advice, Matter Q&A, external legal authority retrieval, signed URLs, browser-direct upload, and Live expansion are deferred.
